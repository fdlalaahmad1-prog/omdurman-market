# سوق أمدرمان — مشروع سوق إلكتروني Full-stack

هذه نسخة أولية كاملة من جهة الخادم والواجهة، وليست مجرد ملف HTML مستقل. تتضمن:
- خادم Node.js/Express وواجهة عربية RTL متجاوبة.
- قاعدة بيانات SQLite تحفظ المستخدمين والمنتجات والطلبات وطلبات انضمام التجار.
- تسجيل حساب ودخول وخروج، وتخزين كلمات المرور بصيغة hash باستخدام bcrypt.
- سلة في المتصفح مع تحقق من المخزون والأسعار على الخادم عند إنشاء الطلب.
- لوحة إدارة لإضافة المنتجات وتعديلها، ومتابعة الطلبات وتحديث حالتها ومراجعة طلبات التجار.
- بيانات منتجات تجريبية لعرض طريقة العمل.

## متطلبات التشغيل
- Node.js 20 أو أحدث.
- اتصال إنترنت أول مرة لتنزيل حزم npm.
- لا تحتاج إلى تثبيت SQLite منفصلًا؛ حزمة `better-sqlite3` تستخدم ملف قاعدة بيانات محليًا.

## التشغيل على جهازك
1. فك ضغط الملف.
2. افتح Terminal/PowerShell داخل مجلد المشروع.
3. نفّذ `npm install`.
4. انسخ `.env.example` إلى ملف باسم `.env`.
5. غيّر `SESSION_SECRET` إلى قيمة طويلة وعشوائية، وضع بريد وكلمة مرور قوية للمدير في `ADMIN_EMAIL` و`ADMIN_PASSWORD`.
6. نفّذ `npm start`.
7. افتح `http://localhost:3000`.

في Windows PowerShell يمكن نسخ ملف الإعدادات هكذا:
`Copy-Item .env.example .env`

في macOS/Linux:
`cp .env.example .env`

## لوحة الإدارة
افتح `http://localhost:3000/admin.html` بعد تشغيل الخادم، ثم سجّل الدخول بحساب المدير الذي تحدده في `.env` من زر «حسابي» في واجهة المتجر. إذا أُنشئت قاعدة البيانات قبل إعداد متغيرات المدير، أعد تشغيل الخادم بعد ضبطها؛ سيُنشأ المدير عند بدء التشغيل إذا لم يكن البريد موجودًا.

## مهم جدًا قبل النشر العام
هذه قاعدة بداية قابلة للتطوير وليست مراجعة أمنية أو إطلاقًا تجاريًا مكتملًا. قبل استقبال عملاء حقيقيين:
- انشر خلف HTTPS، واستخدم `SESSION_SECRET` قويًا، واضبط `NODE_ENV=production`.
- استبدل مخزن جلسات Express الافتراضي بمخزن جلسات دائم مناسب للإنتاج.
- نفّذ نسخًا احتياطيًا دوريًا لقاعدة البيانات، ومراقبة وسجلات وأدوات استعادة.
- أضف سياسة خصوصية وشروط استخدام وآلية حذف الحسابات وطلبات البيانات.
- اختبر حماية CSRF ومعدلات الطلبات، وأجرِ مراجعة أمنية مستقلة.
- أضف إدارة صور المنتجات ورفعها إلى تخزين ملفات آمن، لا تستخدم روابط مجهولة.
- اربط شركة توصيل/إجراءات تسليم واضحة ووسائل الدفع المحلية بعد التعاقد والاختبار. لا توجد بوابة دفع حقيقية في هذا المشروع.
- إعداد واتساب ليس مفعّلًا افتراضيًا؛ متغير `STORE_WHATSAPP` موجود في المثال فقط ولم تُربط به عملية إرسال الطلبات بعد.
- راجع العملة والأسعار والمخزون مع التجار؛ البيانات الحالية أمثلة توضيحية وليست عروضًا حقيقية.
- أضف أدوار التاجر وواجهته الخاصة قبل السماح للتجار بإدارة منتجاتهم مباشرة؛ نموذج الانضمام الحالي يرسل طلبًا للإدارة فقط.
- قاعدة SQLite مناسبة للبدء المحلي والزيارات المحدودة، وقد تحتاج قاعدة بيانات مُدارة مثل PostgreSQL عند التوسع.

## نقاط تقنية
- كل الطلبات محفوظة في SQLite داخل مجلد `data/`.
- يمكن تجربة صحة الخادم من `GET /api/health`.
- API تسجيل الحساب: `POST /api/auth/register`
- API الدخول: `POST /api/auth/login`
- API المنتجات: `GET /api/products`
- API الطلبات: `POST /api/orders` (يتطلب تسجيل الدخول)
- جميع مسارات `/api/admin/*` تتطلب دور admin.
